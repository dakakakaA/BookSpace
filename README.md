## 📚 О проекте

**BookSpace** — учебный проект информационной системы электронной библиотеки. Приложение предназначено для организации работы с библиотечными данными через веб-интерфейс.

Проект построен на модульной архитектуре: frontend отвечает за взаимодействие с пользователем, backend обрабатывает запросы и бизнес-логику, а PostgreSQL используется для хранения данных.

Приложение запускается с помощью Docker Compose, что упрощает настройку окружения и совместный запуск компонентов системы.

## ✨ Возможности

- **Веб-интерфейс библиотеки** — взаимодействие с системой через браузер.
- **Работа с каталогом книг** — пользовательские сценарии, связанные с библиотечными данными.
- **Пользовательские сценарии** — 60 пользовательских историй, оформленных в GitHub Issues.
- **Разделение компонентов** — отдельные frontend, backend и база данных.
- **REST API** — обработка запросов между клиентской частью и сервером.
- **Валидация данных** — проверка входных данных на стороне backend.
- **Контейнеризация** — запуск приложения и зависимостей через Docker Compose.

> Полный перечень реализованных функций следует сверить с текущим кодом приложения: пользовательские истории описывают запланированные сценарии и сами по себе не подтверждают, что каждый сценарий уже реализован.

## 🛠 Технологический стек

- **Backend:** Python, FastAPI
- **Database:** PostgreSQL 15
- **Frontend:** HTML5, CSS3, JavaScript
- **Web server:** Nginx
- **Инфраструктура:** Docker, Docker Compose
- **API:** HTTP, JSON

## 🏗 Архитектура

```text
Пользователь
     |
     v
Frontend (HTML / CSS / JavaScript)
     |
     | HTTP-запросы, JSON
     v
Backend (Python / FastAPI)
     |
     | SQL-запросы
     v
PostgreSQL 15

Nginx — раздача frontend
Docker Compose — запуск сервисов
```

Frontend предоставляет пользовательский интерфейс и отправляет запросы к API. Backend обрабатывает запросы, выполняет прикладную логику и взаимодействует с базой данных. PostgreSQL хранит данные системы, Nginx обслуживает статические файлы frontend, а Docker Compose координирует запуск контейнеров.

## 🚀 Быстрый запуск

### Требования

- Docker Desktop для Windows/macOS или Docker Engine для Linux;
- Docker Compose v2;
- доступ к интернету для загрузки образов при первом запуске.

### 1. Клонирование репозитория

```bash
git clone https://github.com/dakakakaA/BookSpace.git
cd BookSpace
```

### 2. Настройка окружения

Если в корне проекта присутствует `.env.example`, создайте файл `.env`.

**Windows PowerShell:**

```powershell
Copy-Item .env.example .env
```

**Linux/macOS:**

```bash
cp .env.example .env
```

Проверьте параметры подключения к базе данных и остальные переменные окружения, предусмотренные проектом. Не публикуйте секреты и пароли в GitHub.

Если файл `.env.example` отсутствует, ориентируйтесь на конфигурацию в `docker-compose.yml` и документацию проекта.

### 3. Запуск приложения

В корневой папке проекта выполните:

```bash
docker compose up --build -d
```

Проверить состояние контейнеров можно командой:

```bash
docker compose ps
```

### 4. Адреса сервисов

- **Веб-интерфейс:** [http://localhost:8080](http://localhost:8080)
- **Backend API:** работает внутри Docker-сети на порту `8000`.
- **Swagger / OpenAPI:** `/docs` на backend, если соответствующий маршрут доступен и порт опубликован либо запрос проходит через настроенный прокси.

### Остановка приложения

```bash
docker compose down
```

> Команда `docker compose down -v` дополнительно удаляет связанные Docker volumes. Не используйте её, если хотите сохранить данные базы данных.

## 🔒 Безопасность и конфигурация

- Не храните токены, пароли и другие секреты в исходном коде.
- Исключайте локальный `.env` из Git с помощью `.gitignore`.
- Используйте `.env.example` для описания необходимых переменных без реальных секретов.
- Проверяйте права доступа и корректность входных данных на стороне backend.

## 🎯 Цель проекта

BookSpace демонстрирует разработку веб-информационной системы с разделением frontend и backend, использованием реляционной базы данных, REST API и контейнеризацией приложения.

Проект также включает формализацию пользовательских требований через Use Cases и организацию задач средствами GitHub Issues.
