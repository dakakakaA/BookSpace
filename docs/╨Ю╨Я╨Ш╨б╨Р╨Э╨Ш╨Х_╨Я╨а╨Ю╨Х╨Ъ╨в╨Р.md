# BookSpace — описание проекта и архитектура

## 1. Назначение
BookSpace — веб-система электронной библиотеки. Посетитель может зарегистрироваться и войти, читатель — искать книги и управлять собственными выдачами, администратор — поддерживать каталог и контролировать работу системы.

## 2. Архитектура

```text
Браузер (HTML + CSS + Vanilla JS)
             │ HTTP / JSON
             ▼
       Nginx :80 (контейнер frontend)
             │ /api/* proxy
             ▼
       FastAPI :8000 (контейнер backend)
       ├── Auth/JWT + роли
       ├── Books API
       ├── Categories API
       ├── Loans API
       └── Audit + Admin stats
             │ SQLAlchemy / psycopg2
             ▼
       PostgreSQL 15 (контейнер db)
```

Запуск через Docker Compose поднимает ровно три сервиса: `frontend`, `backend`, `db`. Данные PostgreSQL сохраняются в именованном томе `bookspace_data`.

## 3. Технологии и зачем они нужны
- **FastAPI** — HTTP API и автоматическая документация `/docs`.
- **Pydantic v2** — валидация входных данных и схем ответов.
- **SQLAlchemy 2** — ORM, связи и запросы к базе.
- **PostgreSQL 15** — постоянное хранение пользователей, книг, категорий, выдач и аудита.
- **JWT** — токен авторизации для защищённых API-запросов.
- **Vanilla JS** — клиентская одностраничная оболочка без сборщика и стороннего JS-фреймворка.
- **Nginx** — отдаёт статику и перенаправляет `/api/` на FastAPI.
- **Docker Compose** — согласованный запуск трёх контейнеров.

## 4. Модель данных
- `users`: логин, email, хеш пароля, роль `Client` или `Admin`.
- `categories`: название и описание категории; категория может быть отключена.
- `books`: название, автор, уникальный ISBN, категория, год, описание, общий и доступный остаток.
- `loans`: читатель, книга, дата выдачи, срок возврата, фактическая дата возврата и статус.
- `audit_logs`: кто, когда и какое действие выполнил над сущностью.

Связи: одна категория содержит много книг; у пользователя много выдач; у книги много записей выдачи. Книга не удаляется физически из каталога при обычном удалении: она скрывается через `is_active`, чтобы сохранить историю.

## 5. Основные сценарии
1. Регистрация создаёт клиента, пароль сохраняется только в хешированном виде.
2. Вход проверяет пароль и выдаёт JWT.
3. Защищённые запросы проверяют токен; административные маршруты дополнительно проверяют роль.
4. Каталог поддерживает поиск по названию, автору и ISBN, фильтр категории и наличие.
5. Выдача уменьшает `available_copies`; возврат увеличивает его и меняет статус выдачи.
6. Система блокирует выдачу при нулевом остатке и ограничивает читателя пятью активными выдачами.
7. Администратор добавляет, редактирует и скрывает книги, просматривает статистику и аудит.

## 6. API маршруты
- `POST /api/auth/register`, `POST /api/auth/login`, `GET /api/auth/me`
- `GET /api/books`, `GET /api/books/{id}`, `POST /api/books`, `PUT /api/books/{id}`, `DELETE /api/books/{id}`
- `GET /api/categories`, `POST /api/categories`, `PUT /api/categories/{id}`, `DELETE /api/categories/{id}`
- `GET /api/loans`, `POST /api/loans`, `POST /api/loans/{id}/return`
- `GET /api/admin/audit`, `GET /api/admin/stats`
- `GET /api/health`

`POST/PUT/DELETE` каталога и `admin`-маршруты требуют роль администратора. Создание выдачи и возврат требуют авторизации; читатель может управлять только своими выдачами.

## 7. Запуск и проверка
1. Установить Docker Desktop и запустить его.
2. В корневой папке проекта выполнить `docker compose up --build`.
3. Открыть `http://localhost:8080`.
4. Документация API: `http://localhost:8080/docs`.
5. Проверка сервиса: `http://localhost:8080/api/health`.

Демо-пользователи: `client / client123`; администратор: `admin / admin123`. Это демонстрационные учётные данные — для публичного развёртывания обязательно заменить пароли, `SECRET_KEY` и пароль БД.

## 8. Границы текущей версии
Восстановление пароля, email-уведомления, продление и очередь ожидания, импорт/экспорт, редактирование категорий через UI и CI-тесты запланированы, но не входят в реализованный MVP. Текущая выдача реализована как учёт экземпляров в библиотеке, а не как DRM-защита цифровых файлов.
